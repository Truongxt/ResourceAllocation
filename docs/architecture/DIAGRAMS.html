🔐 Luồng Đăng nhập & Xoay vòng Token
sequenceDiagram
    autonumber
    actor User as Client (Web/Mobile)
    participant Auth as Auth Controller
    participant DB as MongoDB
    participant Cookie as HttpOnly Cookie

    User->>Auth: POST /api/auth/login { email, password }
    Auth->>DB: Tìm User & kiểm tra bcrypt hash
    alt Đăng nhập đúng
        Auth->>Auth: Sinh AccessToken (15m) & RefreshToken (7d)
        Auth->>DB: Lưu bản băm RefreshToken vào DB
        Auth->>Cookie: Set-Cookie: refreshToken (httpOnly, Path=/api/auth)
        Auth-->>User: Trả { accessToken, user }
        User->>User: Lưu accessToken vào RAM (tokenStore.js)
    else Sai thông tin
        Auth-->>User: 401 Unauthorized
    end
Bảo mật cao cấp: Access Token chỉ lưu trong bộ nhớ RAM tạm thời, không lưu vào localStorage để triệt tiêu lỗ hổng XSS. Refresh Token được bảo vệ trong HttpOnly Cookie.
🔄 Luồng Tự động Cấp lại Token (Silent Refresh)
sequenceDiagram
    autonumber
    actor Axios as Axios Interceptor
    participant Server as Express Server
    participant DB as MongoDB

    Axios->>Server: Gửi Request (Token đã hết hạn)
    Server-->>Axios: 401 TokenExpiredError
    Note over Axios: Interceptor bắt mã 401
    Axios->>Server: POST /api/auth/refresh-token (Cookie)
    Server->>DB: Kiểm tra hash RefreshToken
    alt Hợp lệ
        Server->>Server: Xoay vòng Token (Tạo cặp mới)
        Server->>DB: Cập nhật RefreshToken mới
        Server-->>Axios: Set-Cookie mới + Trả AccessToken mới
        Axios->>Axios: Cập nhật RAM tokenStore
        Axios->>Server: Tự động chạy lại Request ban đầu
        Server-->>Axios: 200 OK Thành công
    else Không hợp lệ
        Server-->>Axios: 403 Forbidden
        Axios->>Axios: Chuyển về /login
    end
Trải nghiệm mượt mà: Người dùng không bao giờ bị gián đoạn hay bất ngờ bị văng khỏi hệ thống khi đang làm việc; token được tự động làm mới ngầm bên dưới.
🛡️ Kiểm tra Ràng buộc Tiền nhiệm & Chống Chu trình (DAG)
flowchart TD
    Start([Lưu Task Dependency]) --> C1{Phụ thuộc chính nó?}
    C1 -- Có --> E1[Báo lỗi: Tự phụ thuộc]
    C1 -- Không --> C2{Cùng dự án?}
    C2 -- Không --> E2[Báo lỗi: Khác dự án]
    C2 -- Có --> Graph[Xây dựng đồ thị có hướng DAG]
    Graph --> C3{Phát hiện chu trình vòng lặp?}
    C3 -- Có --> E3[Báo lỗi: Tạo vòng lặp vô tận]
    C3 -- Không --> Save[(Lưu Task vào Database)]
    Save --> Recalc[Tính lại % tiến độ Dự án]
    Recalc --> Done([Hoàn tất])
Thuật toán đồ thị DAG: Ngăn chặn hoàn toàn lỗi logic trong quản lý dự án (Ví dụ: A chờ B, B chờ C, C lại chờ A).

🧬 Vòng lặp Thuật toán Di truyền (Genetic Algorithm)
flowchart TD
    Start([Khởi tạo Tasks & Nhân sự]) --> Pop[Khởi tạo Quần thể: N Nhiễm sắc thể]
    Pop --> Fit[Đánh giá Fitness Đa mục tiêu: Cân bằng tải, Kỹ năng, Chi phí, Quá tải]
    Fit --> Check{Hội tụ hoặc Đạt thế hệ Max?}
    Check -- Có --> Best[Trích xuất Cá thể Ưu tú nhất]
    Check -- Không --> Elite[Giữ 5% Cá thể Tinh hoa]
    Elite --> Tour[Chọn lọc Tournament k=5]
    Tour --> Cross[Lai ghép Uniform Crossover rate=0.8]
    Cross --> Mut[Đột biến Random Mutation rate=0.1]
    Mut --> Next[Hình thành Quần thể thế hệ mới]
    Next --> Fit
    Best --> SaveResult[(Lưu OptimizationResult)]
Đa mục tiêu (Multi-objective): Cân bằng đồng thời 4 hàm mục tiêu: Độ lệch chuẩn tải nhân sự, Độ phù hợp kỹ năng, Chi phí thực hiện và Triệt tiêu quá tải.
⚙️ Quy trình Thuật toán Lai (Hybrid CSP ➔ GA)
flowchart TD
    Data[Tập hợp Tasks & Nhân sự] --> CSP[CSP Solver Engine]
    CSP --> NodeCons[Kiểm tra Node Consistency]
    NodeCons --> AC3[Lan truyền Ràng buộc AC-3: Lọc H1-H4]
    AC3 --> Domains[Thu hẹp Miền giá trị Khả thi]
    Domains --> GA[GA Engine: Tìm kiếm Tối ưu trên Miền hẹp]
    GA --> Comp[Ma trận So sánh 9 Chỉ số Định lượng]
    Comp --> Apply[Áp dụng Phương án Phân công]
Ưu việt của Hybrid: CSP loại bỏ triệt để các phép gán vi phạm ràng buộc cứng trước khi GA tiến hành tối ưu hóa, giúp tốc độ hội tụ nhanh gấp 3–5 lần và loại bỏ nghiệm không khả thi.
📊 Thuật toán Phân tích Đường găng (Critical Path Method - CPM)
flowchart LR
    subgraph S1 ["1. Forward Pass (Duyệt xuôi)"]
        F1["ES = Max(EF các tiền nhiệm)"]
        F2["EF = ES + Thời lượng công việc"]
    end

    subgraph S2 ["2. Backward Pass (Duyệt ngược)"]
        B1["LF = Min(LS các công việc sau)"]
        B2["LS = LF - Thời lượng công việc"]
    end

    subgraph S3 ["3. Độ thả nổi (Total Float)"]
        TF["Total Float (TF) = LS - ES = LF - EF"]
    end

    subgraph S4 ["4. Phát hiện Đường găng"]
        CP["Các công việc có TF = 0 ➔ Đường găng (Màu Đỏ)"]
    end

    S1 --> S2 --> S3 --> S4
Đường găng (Critical Path): Xác định chuỗi công việc quyết định thời gian hoàn thành của toàn bộ dự án. Bất kỳ sự chậm trễ nào trên đường găng đều sẽ làm trễ ngày bàn giao dự án.
🧪 Quy trình Thực nghiệm Đối chứng Thuật toán (Benchmark Studio)
sequenceDiagram
    autonumber
    actor Tester as Nghiên cứu viên / Hội đồng
    participant Studio as Benchmark Studio UI
    participant Gen as Synthetic Generator
    participant Runner as Benchmark Runner
    participant GA as Genetic Algorithm
    participant CSP as CSP Solver
    participant Hybrid as Hybrid Engine

    Tester->>Studio: Chọn bộ dữ liệu (Small 20t / Medium 100t / Large 500t / Live DB)
    Studio->>Gen: Sinh dữ liệu ngẫu nhiên theo phân phối chuẩn
    Studio->>Runner: Kích hoạt chạy đối chứng song song
    par Chạy GA
        Runner->>GA: Chạy GA (100 cá thể, 500 thế hệ)
        GA-->>Runner: Thời gian (ms), Fitness, Độ lệch chuẩn tải
    and Chạy CSP
        Runner->>CSP: Chạy CSP (AC-3 + MRV + LCV)
        CSP-->>Runner: Thời gian (ms), Tỉ lệ khả thi, Vi phạm
    and Chạy Hybrid
        Runner->>Hybrid: Chạy CSP lọc miền ➔ GA tối ưu
        Hybrid-->>Runner: Tỉ lệ thu hẹp miền (%), Fitness tối ưu, Thời gian
    end
    Runner-->>Studio: Xuất Bảng so sánh 3 cột + Biểu đồ Radar + Kết luận đối chứng
    Studio-->>Tester: Trực quan hóa số liệu phục vụ Thuyết minh Đồ án
Phục vụ Đồ án Tốt nghiệp: Cung cấp đầy đủ bằng chứng thực nghiệm định lượng để chứng minh tính hiệu quả và tính khả thi của các thuật toán đề xuất trên nhiều quy mô bài toán khác nhau.
